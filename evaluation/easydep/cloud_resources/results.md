# VM 의존성 KB 제거 실험 결과

> 최초 실행: 2026-08-05, 독립 gold 재평가: 2026-08-07
> 성격: 결정론적 구성요소 검사

각 사례에서 같은 시작 리소스를 주고, `full`은 `depkb`의 연쇄 의존 자원 집합을 조회하며
`no-cloud-kb`는 조회를 실제로 건너뛰었다.

| 사례 | 조건 | 노드 F1 | 간선 F1 | 순서 위반 |
|---|---|---:|---:|---:|
| AWS 공개 LB | full | 0.857 | 0.571 | 0 |
| AWS 공개 LB | no-cloud-kb | 0.400 | 0.000 | 0 |
| Azure VM | full | 1.000 | 1.000 | 0 |
| Azure VM | no-cloud-kb | 0.400 | 0.000 | 0 |
| GCP VM | full | 0.750 | 0.571 | 0 |
| GCP VM | no-cloud-kb | 0.333 | 0.000 | 0 |
| **매크로 평균** | **full** | **0.869** | **0.714** | **0** |
| **매크로 평균** | **no-cloud-kb** | **0.378** | **0.000** | **0** |

독립 검토는 기존 개발용 gold보다 넓은 필수 집합을 판정했다. full도 AWS의 공급자 생성 NIC
및 관련 관계, GCP의 기본 Network·Subnet 관계를 놓쳤다. KB 제거판은 세 사례 모두 모든
간선을 누락했다. 순서 위반이 0인 이유는 제거판에 검사할 간선 자체가 없기 때문이며,
올바른 순서를 뜻하지 않는다.

## 해석 한계

이 결과는 KB 조회 경로가 실제로 작동하고 제거 시 어떤 정보가 사라지는지를 확인한다.
gold는 시스템 출력을 보지 않은 AI clean-room 검토로 분리했으므로 종전의 순환 정답 문제는
줄었지만, 인간 전문가 검토를 대체하지 않는다. 검토자는 공급자 생성 자원을 포함할지와
`direct` 관계의 범위가 해석될 수 있음을 기록했다. 따라서 논문에는 이 한계를 공개하고,
전체 시스템 효과는 동결된 종단 입력과 최종 소스·Dockerfile·Terraform 구현물의 독립
검사 결과로 판단한다.

## VM 용량·가격·성능 지식 제거 실험

2026-08-06에 동결한 여섯 개발 사례를 `full`과 `no-vm-knowledge`로 각각 실행했다.
정상 선택은 AWS·Azure·GCP 2 vCPU·4 GiB 상시 부하이며, 나머지는 HA 예산 충돌,
최소 용량 누락, 가격 스냅샷에 없는 리전이다.

| 조건 | 통과 사례 | 평균 검사 점수 |
|---|---:|---:|
| full | 6/6 | 1.000 |
| no-vm-knowledge | 0/6 | 0.000 |

full은 세 정상 사례에서 용량·컴퓨트 예산을 만족하면서 성능 경고가 없는 후보를 선택했고,
세 예외 사례를 각각 `infeasible` 또는 구체적 사유의 `deferred`로 판정했다. 제거군은
카탈로그를 호출하지 않고 `knowledge_unavailable`을 반환했다. 원시 입력·출력·채점 결과는
`artifacts/runs/easydep-{full|no-vm-knowledge}-*-20260806T0210*`에 있다.

이 수치는 VM 지식 경로가 요구된 판정을 제공한다는 배선 증거다. 제거군을 일부러 빈
지식으로 만든 결정론적 비교이므로 일반 앱 품질이나 LLM 대비 우월성의 효과 크기는 아니다.
SKU 정답도 동결 스냅샷에 종속된다. 종단 결론은 동일 입력의 CoT·MetaGPT·EasyDep 최종
구현물을 공통 평가기로 검사한 결과가 있어야 한다.
