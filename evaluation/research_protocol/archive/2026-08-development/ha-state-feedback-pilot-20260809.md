# HA–노드 상태 질문·수정 파일럿

## 목적

자연어 요구사항에서 생성된 애플리케이션이 노드 파일시스템 상태를 사용하면서 다중
영역 가용성을 요구할 때, 시스템이 이를 질문하고 사용자 선택 뒤 같은 구현 작업에서
수정하는지 확인했다. 특정 데이터베이스나 마운트 경로를 정답으로 두지 않았다.

입력은 다음 한 문장이다.

> Create a Dockerized REST service that persists mutable application state on the VM filesystem and remains available across an availability-zone failure.

사용자 선택은 `externalize-or-replicate-state`였다. 이는 외부 상태 서비스와 명시적
복제 중 어느 기술을 강제하지 않고, 노드 하나에만 묶인 상태를 제거하라는 결정이다.

## 관찰

실제 무료 LLM endpoint를 사용했다. 실행마다 워크스페이스를 제거했고 클라우드
리소스는 생성하지 않았다.

| 시도 | LLM 관찰 | 결과 |
|---|---|---|
| 1 | 18.54초 + 9.83초 | 최초 `BIND-STATE-HA-001` 탐지, 선택 후에도 같은 충돌. 당시 측정기는 콘솔에만 출력하여 원시 JSON 파일은 남지 않았다. |
| 2 | 18.58초 | LLM이 낸 선언 계약이 스키마 검증에 실패. [원시 결과](../../measurements/2026-08-development/ha-state-feedback-pilot-20260809-attempt-2.json) |
| 3 | 14.52초 | 생성물이 요구한 파일 상태를 구현하지 않았고 진단기도 이를 잡지 못해 `completed`. [원시 결과](../../measurements/2026-08-development/ha-state-feedback-pilot-20260809-attempt-3.json) |
| 4 | 실행됨 | 진단 직렬화기의 모델 가정 때문에 결과 저장 실패. 워크스페이스 정리는 성공했다. |
| 5 | 16.81초 | 시도 3과 같은 거짓 음성. [원시 결과](../../measurements/2026-08-development/ha-state-feedback-pilot-20260809-attempt-5.json) |

반복 성공을 얻기 위해 무제한 재시도하지 않았다. 현재 증거는 실제 LLM에서 충돌
탐지가 한 번 관찰되었다는 것과, 탐지·수정 성공이 안정적이지 않다는 것을 함께
보여준다.

## 발견한 일반 결함과 보완

1. 수정 응답을 기존 `src/main`에 덮어쓰면 LLM이 생략한 과거 로컬 상태 파일이
   남았다. 사용자 합의에 따른 수정에서는 production source를 완전한 스냅샷으로
   교체하고, 재검증 실패 시 이전 스냅샷을 복원하도록 바꿨다.
2. 파일 상태 관측기가 stream 생성 API만 보아 `Files.writeString`, `Files.write` 등의
   일반 Java API를 놓쳤다. 상태 의미가 있는 환경 변수·절대 경로와 파일 API가 함께
   있을 때만 노드 상태로 판정하도록 API 집합을 확장했다. 로그 경로는 계속 제외한다.
3. 측정기는 `ConsistencyDiagnostic`과 일반 `Diagnostic`을 모두 직렬화하도록 바꿨다.

관련 회귀시험은 통과했다. 그러나 이 보완만으로 자연어 요구사항 준수를 보장하지
않는다. LLM이 파일 상태 요구 자체를 구현하지 않으면 산출물 관측만으로는 “요구가
사라졌다”와 “공유 상태로 바뀌었다”를 구별할 수 없다.

## 주장 경계와 다음 보완

- 입증됨: 계약 진단 규칙, 질문 대안, 체크포인트 보존·원자적 수정의 결정론적 경로.
- 관찰됨: 실제 LLM이 충돌을 탐지한 실행 1회와 거짓 음성/스키마 실패.
- 미입증: 실제 LLM의 안정적인 질문→수정 성공, 앱 빌드·업무 기능, 실제 클라우드 HA.

다음 보완은 키워드 규칙을 계속 늘리는 것이 아니다. 요구사항 단계가 수락한
애플리케이션 상태 의도를 기존의 열린 `ContractFact`로 전달하고, 구현에서 관측한
사실과 분리해 대조해야 한다. 새 고정 스키마 필드를 추가하지 않고 다음 두 질문만
검증한다.

1. 요구된 상태 성질이 구현 산출물에서 사라졌는가?
2. 다중 영역일 때 그 상태의 공유·복제 방식이 명시됐는가?

이 연결이 생기기 전에는 HA 사용자 피드백 종단 성공을 주장하지 않는다.
