# 측정 타당성 재검토

## 재검토 결론

현재 구성요소 projection은 리소스와 참조 관계의 **정적 관찰**까지만 측정한다. 관계의 카디널리티, 가용 영역 제약, 게스트 포맷·마운트 완료는 별도 기능 게이트가 없으면 점수에 포함하지 않는다. 따라서 이 결과만으로 실제 배포 가능성이나 애플리케이션 기능 성공을 주장하지 않는다.

## 이번에 바로잡은 경계

- 영속 경로를 `/var/lib/notes` 같은 사례 상수로 판정하지 않고, 평가 사례의 `persistenceAcceptance.mountPath`를 관찰기에 전달한다.
- 마운트 명령에서 다른 경로가 발견되어도 계약 경로와 다르면 `mount` 구성요소 통과로 세지 않는다.
- `requiredDependencies` 원본 배열이 비어 있어도, 실행 시 선택한 provider와 component delta로부터 공식 근거가 연결된 필수 참조 관계를 기계적으로 파생한다.
- 카디널리티와 제약은 현재 `requires-separate-gate`로 남겨 점수 분모에서 제외한다. 단일 참조 쌍을 다대다 또는 다중 영역 충족으로 해석하지 않는다.
- 복구 체크포인트는 디렉터리 존재만 보지 않고 run ID, app ID, 완료 단계, attempt 번호, 애플리케이션 트리 해시가 모두 맞아야 사용한다.
- 잘못된 명시적 복구 소유자는 작업공간 복원보다 먼저 거부한다. 이 순서는 기존 코드에 이미 적용되어 있음을 확인했다.

## 남은 제한

카디널리티와 영역·인증서·게스트 마운트 제약을 범용 정적 분석기로 추론하지 않는다. 필요한 주장은 provider 검증과 실제 기능 게이트에서 각각 확인한다. 이 제한은 오버피팅을 피하기 위한 범위 결정이며, 향후 실험 결과에서 정적 구성요소 점수와 기능 성공률을 분리해 보고한다.
