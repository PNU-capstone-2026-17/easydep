# 구현 작업 흐름

이 디렉터리는 planner가 만든 작업을 실행 순서대로 조정하고, 완료 결과와 수리 결과를
검사한다. 소스 코드의 업무 로직을 직접 생성하는 곳은 아니다.

## 입력과 출력

- 입력은 `JobSpec`, `run-manifest.json`, 구현 작업 결과와 검증 결과다.
- 출력은 실행 상태, 수리 계획, 완료 보고서와 `rtm-traceability-map.json`이다.
- RTM은 `TaskSpec`의 요구사항·유스케이스·`source_refs`와 실제 생성 파일을 연결한다.
  prompt 문자열이나 비슷한 파일 이름을 분석해 출처를 만들어 내지 않는다.

## 파일 소유 판단

`required_output_paths`는 한 작업이 반드시 완성해야 하는 파일이다. 여러 작업의
`allowed_write_paths`에 같은 파일이 들어 있어도 필수 산출물 소유자를 우선한다. 필수
소유자가 없고 편집 후보가 한 작업뿐일 때만 그 작업을 시작 힌트로 사용한다. 이 목록은
OpenHands가 필요한 관련 파일을 읽는 것까지 막는 보안 경계가 아니다.

## 실패 조건

필수 산출물이 없거나 task와 실행 결과가 맞지 않으면 완료로 저장하지 않는다. 외부 단계의
설계를 이름으로 추측해 고치지 않고, 확인된 요구사항·설계 주소를 상위 조정 계층에 돌려준다.
