# Docker-on-VM 지식베이스 범위

## 1. 목표 환경

- CSP: AWS, Azure, GCP
- 실행 단위: Linux VM 위의 Docker 컨테이너
- 애플리케이션: 하나 이상의 Docker 워크로드
- 산출물: CSP 중립 계획, 배포 다이어그램, CSP별 IaC와 실행 설정

학부 졸업과제에서 재현 가능한 범위를 확보하기 위해 Kubernetes, VPN, 서버리스와 관리형
애플리케이션 플랫폼은 다루지 않는다.

## 2. 포함하는 리소스

| 중립 리소스 | 역할 | 선택 시점 |
|---|---|---|
| network | 격리된 가상 네트워크 | 의존 폐포 |
| subnet | VM이 연결되는 네트워크 구역 | 의존 폐포 |
| firewall | 허용 포트와 통신 방향 | 설계·의존 폐포 |
| publicIp | 직접 외부 진입이 필요할 때 | 설계 |
| loadBalancer | 복수 VM 또는 단일 장애 허용 불가 시 진입점 | 설계 |
| vm | Docker 호스트 | 항상 시작 리소스 |
| disk | 재시작·재생성 뒤에도 보존할 데이터 | 설계 |
| image | VM 부팅 이미지 카탈로그 선택 | 구현 계획 |
| sshKey / identity | VM 접근 또는 권한 부여 | 구현 계획 |

리소스 이름은 CSP 중립 개념이다. 실제 IaC 생성 단계에서 AWS·Azure·GCP 타입으로 변환한다.

## 3. 제외하는 리소스

- Kubernetes cluster, node group, ingress, service, PVC
- VPN과 온프레미스 연결
- 함수형·서버리스 컴퓨팅
- 관리형 데이터베이스, 메시지 큐, 오브젝트 스토리지
- CSP 간 네트워크와 멀티클라우드 단일 배포

애플리케이션이 데이터베이스를 필요로 하면 연구 범위에서는 VM 컨테이너와 영속 디스크로
배포한다. 관리형 DB 추천은 하지 않는다.

## 4. 단계별 결정 경계

| 단계 | 결정하는 것 | 결정하지 않는 것 |
|---|---|---|
| 요구사항 | 예산, CSP/지역 제한, 진입·보존·가용성·용량 요구 | VM 수와 제품명 |
| 설계 | Docker 워크로드, 연결, 포트, 영속성, 외부 진입 구조 | VM 제품군·정확한 가격 |
| 구현 | 의존 폐포, VM·디스크·LB 수량, CSP별 IaC, 용량 근거가 있을 때 VM 후보 | 검증되지 않은 부하→용량 추정 |
| 테스팅 | 생성 애플리케이션 테스트 | 새로운 설계 결정, 실험군 전용 채점 |

## 5. 범위 준수 조건

다음을 모두 만족해야 VM 전용이라고 부른다.

1. 제품 질의 결과에 제외 리소스가 나타나지 않는다.
2. 공개 API가 제외 리소스를 시작점으로 받지 않는다.
3. 기본 데이터와 테스트 골드셋이 세 CSP의 포함 리소스만 사용한다.
4. 배포 다이어그램과 IaC가 Docker-on-VM 구조만 생성한다.
5. 범위 밖 요구는 조용히 변환하지 않고 `unsupported`로 보고한다.

## 6. 현재 구현 상태

오케스트레이션의 설계 경로는 `vm`, `disk`, `loadBalancer`만 시작점으로 사용한다.
`depkb/claims.json`은 VM 범위 주장만 포함하고 공개 함수는 K8s·VPN·파일시스템 시작점을
거부한다. 현재 주장에 인용되는 VM 실험 22개만 제품 실험 디렉터리에 남겼다.
요구사항 관심사도 VM 실측에 맞춰 5개로 줄였으며, 인용한 depkb 21좌표의 실재·유일성과
K8s·PVC·Ingress·VPN 좌표의 부재를 자동 검사한다.

다른 멤버 영역의 과거 Kubernetes 생성기는 수정하지 않는다. 새 오케스트레이션은 그 코드가
애플리케이션 소스를 만든 뒤 별도 구현 경계에서 AWS·Azure·GCP Docker-on-VM Terraform만
생성한다. 내부 테스팅 경계는 애플리케이션 테스트만 수행하고, Docker와 IaC 검사는 실험의
외부 공통 평가기가 모든 비교군에 동일하게 수행한다. 디스크 앵커는 설계 그림의 DB 노드가
아니라 요구사항 분석의 `persistent_storage.required`만 근거로 삼는다.
IaC 생성 에이전트에는 `depkb`의 한국어 사용자 설명을 넘기지 않고 CSP·리소스 역할·간선·
생성 순서·기계 판독 제약만 영어 시스템 입력의 JSON 필드로 전달한다.

VM 제품군·용량·가격·성능 추천은 설계가 아니라 구현 경계에서 수행한다. 3사 VM 카탈로그와
결정론적 후보 필터를 연결했으며, 최소 vCPU·메모리가 없는 일반 종단 사례에서는 추천을
보류한다. 최소 용량을 동결한 별도 여섯 사례에서만 RQ3 구성요소 효과를 평가한다. 선택
기준과 한계는 [`vm-resource-selection.md`](vm-resource-selection.md)에 기록한다.

파일럿에서는 VM IaC 의미 요구를 만족한 사례가 있었지만 핵심 애플리케이션 로직이
`null` 또는 예외 스텁인 채 내부 테스트를 통과한 사례도 있었다. 따라서 배포 구조의 연결은
확인했어도 전체 시스템의 기능적 종단 성공은 아직 입증되지 않았다. 상세 실행 기록은
`evaluation/pilot-results.md`에 둔다.
