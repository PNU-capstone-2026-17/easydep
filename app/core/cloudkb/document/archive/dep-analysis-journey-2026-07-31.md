## 1. 질문과 정의

출발(사용자): *"리소스 의존성이란 무엇이고 어떻게 분석하는가 — 논문 근거 수준으로."*

- **의존성 = 검증 가능한 주장.** "B에 개입하면 A가 달라진다"의 반사실 정식화
  (Parnas uses 관계의 인프라 인스턴스). 참조 유무는 증거의 한 종류이지 정의가 아니다.
- **질문 유형 셋**: 존재(B 없이 A가 만들어지나) · 생명주기(B를 지우면 어떻게
  되나) · **기능**(B를 떼면 A가 남지만 제 일을 하나 — 2026-07-31 신설, §4-2).
  기능 축은 처음에 "대응 실험을 세울 수 없다"며 공백으로 뒀는데, 오라클을
  바꾸자(거부 코드 → 기능 신호) 성립했다. 관계 타입화의 선례는 TOSCA·k8s
  `ownerReferences`.
- **주장은 CSP로 색인된다** — 가설이었고, 실측으로 다섯 번 확인됐다(§5).
- **오라클 서열**: 컨트롤 플레인(apply) > preflight > 원문 스키마 > 우리 가공물
  (오라클 금지). 서열도 실측으로 정당화됐다 — 아래층이 침묵한 것을 위층이 잡는
  사례가 층마다 있다.
- **판정 어휘**: required / optional / holds / unknown. **거부는 증거, 통과·침묵은
  증거가 아니다**(테스트가 강제). 이 규율이 오판 3건을 막았다.

## 2. 실험 전수 — 52라운드 · 873스텝

전부 잔여물 0으로 종료했고, 매 라운드 끝에 세 클라우드 전수 점검을 돌린다
(사용자 지시, 2026-07-31). 총비용은 세 클라우드 합쳐 수천 원 이내.

**전수 목록은 `depkb/experiments/`가 진실이다**(디렉터리 이름이 곧 라운드,

**실험 설계의 규율 넷** (전부 실패에서 얻었다):

1. **CLI를 믿지 않는다** — gcloud·az CLI는 생략 필드에 기본값을 주입해 반사실
   실험을 오염시킨다. gcp는 REST 직접, AKS 생략은 `az rest`.
2. **한 번에 한 축만 흔든다** — 교란 3건(SKU 불가·IGW 부재·허상이 카디널리티를
   가림)이 전부 축 혼입이었다.
3. **거부만으로는 부족하다 — 대우를 확인한다.** 양성 대조가 없으면 "무엇을 해도
   안 된다"와 구별되지 않는다(EKS·VPN에서 실제로 필요했다).
4. **측정 가능한 조건을 먼저 만든다** — gcp 생명주기는 전용 네트워크가, azure는
   사용자 서브넷이 있어야 잴 수 있었다(공용 자원·서비스 합성물은 대상이 아니다).

## 4-2. 셋째 질문 축 — 기능 의존 (2026-07-31 신설)

처음엔 "대응 실험을 세울 수 없다"며 공백으로 뒀다. 성립시킨 것은 **오라클
교체**다: 존재·생명주기는 컨트롤 플레인의 **거부 코드**가 오라클인데, 기능
의존은 정의상 **컨트롤 플레인이 막지 않는 지대**라 거부가 영영 안 나온다.

- **관측 정의 둘**: ① 참조 무결성 — 기능을 깨는 변이를 막는가(막으면 그건
  이미 생명주기 결속이다). ② **기능 신호** — 변이 후 기능이 실제로 깨지나.
  기능 의존이 고유한 것은 ①이 무방비인 지대다.
- **인과 사다리**: 기능 확인 → 변이 성공(무방비) → 상실 → 복원 → **회복**.
  회복까지 봐야 상실이 변이 탓임이 선다(회복 없이는 우연한 변화와 구별 불가).
- **신호 5종**(2026-07-31 확장). 처음엔 외부 TCP 도달성 하나였고(위협 ④),
  **앱을 도입하지 않고** 게스트 안에서 OS 기본 도구로만 넷을 더 열었다
  (하네스 `experiments/_guest.py`):

  | 신호 | 최소 관측자 | 겨눈 간선 |
  |---|---|---|
  | 도달성(인바운드) | 로컬→VM TCP 22 | nic/vm→publicIp · subnet→firewall |
  | 이름 해석 | `getent hosts` | globalDns→network |
  | 볼륨 I/O | `dd oflag=direct` | vm→disk |
  | 자격증명 | IMDSv2 `curl` | vm→iamRole |
  | 아웃바운드 | VM→외부 HTTPS | subnet→internetGateway |
  | LB 서빙 | LB 프론트엔드로 HTTP | **loadBalancer→vm** |
  | 서비스 디스커버리 | 클러스터 내 이름으로 HTTP | k8sService→k8sCluster |

  **앱을 기준으로 삼지 않은 것이 설계 결정이다** — 앱을 넣으면 주장이 "이
  앱의 이 동작이 깨진다"로 좁아지고 언어·프레임워크가 교란이 된다. 기준은
  앱이 아니라 기능 종류(capability)이고, 앱은 최소 관측자를 만들 수 없을
  때만 도입한다(이 넷은 전부 불필요했다).

실측 8건(3사 × publicIp·firewall + 라우팅 2): 전부 `holds`. 백미는
**azure `nic→publicIp`가 세 질문 전부 판정된 첫 쌍**이다 — 생성엔 선택 ·
붙어 있으면 삭제 거부 · 떼는 건 막지 않지만 기능이 깨진다. `required: true`
한 필드였다면 이 셋은 표현 자체가 불가능했다.

**신호가 갈리지 않은 사례도 남긴다**: EKS IAM(§5-8)은 "새 노드그룹 생성
성공 여부"를 신호로 잡았는데, 노드그룹 생성이 **비동기**라 API 수락 시점과
프로비저닝 시점이 갈렸고 그 사이에 변이를 복원해 판정이 불가능해졌다.
설계 결함이고, 미판정으로 유지한다(`aws-iamfunc-2026-07-31/Z1`).

## 4-3. 합성 — k8s 오브젝트가 클라우드 자원을 만든다

`Service`·`PVC`·`Ingress`는 클라우드 자원이 아니라 **선언문**인데, 선언만으로
클라우드 자원이 생긴다. 그래서 어휘에 넣었다 — 계획층이 이걸 모르면 같은
것을 또 만든다(**이중 생성**).

| 선언 | azure | gcp | aws |
|---|---|---|---|
| Service(LB) | 상시 LB에 규칙+PIP 합성 | **성좌 신설**(FR+targetPool+방화벽3) | CLB+SG (**노드 0에서도**) |
| PVC(RWO) | 디스크 합성 | 디스크 합성 | 디스크 합성 (**IRSA 전제 필요**) |
| PVC(RWX) | 스토리지 계정+공유 합성 | 드라이버 거부 | 미측정(EFS CSI 별도) |
| Ingress | **합성 없음**(기본 구성) | 전역 HTTP LB 성좌 | **합성 없음**(기본 구성) |

전부 `optional + server-implicit`이고 생명주기는 **동반 정리**(삭제 보호의
반대 방향)다. 소비층에서 기제를 가르지 않으면 계획이 "이미 없는 것의 삭제
단계"를 낸다 — `cleanupCascades`가 그 자리다.

**전제 사슬의 길이가 CSP마다 다르다**는 것이 이 절의 둘째 발견이다. aws PVC는
노드그룹·CSI 드라이버·**IRSA**·CSI 프로비저너 SC 넷을 갖춰야 합성이 시작됐고,
azure·gcp는 클러스터만 있으면 됐다. "aws는 안 된다"가 아니라 "aws는 층이 셋
더 있다"가 정확한 진술이다.

## 5. 발견

1. **3사 공통핵**: `subnet→network` 필수 · **생명주기 제약 19건 전부**가 3사
   동형(코드만 다르다: `DependencyViolation`/`InUse…`/`RESOURCE_IN_USE`).
   IaaS뿐 아니라 CNA 층(k8s)에서도 같다.
2. **양상 반전 8**(존재 판정이 CSP로 갈리는 간선): `vm→disk`(gcp만 필수) ·
   `vm→nic`(aws만 선택) · `vm→image`(**aws만 필수** — 기존 볼륨 부팅 경로 부재) ·
   `nic→subnet`(gcp만 선택) · `loadBalancer→subnet`(aws만 필수) ·
   `k8sCluster→subnet`(aws만 필수) · `k8sCluster→k8sNodeGroup`(azure 필수·gcp 선택) ·
   `k8sCluster→iamRole`(**aws 필수 ↔ azure 서버 합성**). **중립 필수 플래그
   하나로는 이 지식을 표현할 수 없다**는 논거의 기둥.

   반전은 판정에만 있지 않다 — **간선의 대상 자체가 갈리는 사례**도 둘이다:
   `customImage`의 원본이 azure·gcp는 디스크인데 aws는 **인스턴스**이고,
   `fileSystem`이 매달리는 곳이 aws는 서브넷(접속점 경유)·gcp는 네트워크·
   azure는 **스토리지 계정**(경로 중첩)이다.
3. **서버 합성·대체 8종**: aws 기본 VPC·default SG·ENI·AMI 루트 볼륨·클러스터 SG ·
   gcp default 네트워크/서브넷·default-pool · azure 노드 RG의 vnet. **CB 드라이버가
   IaaS 층에서 하던 합성을 관리형 서비스가 CNA 층에서 한다.**
4. **존재와 생명주기의 독립**: `nic→firewall`·`nic→publicIp`·`vm→disk` — 생성엔
   선택인데 붙어 있으면 삭제 금지. 한 필드에 눌렀으면 표현 불가능했다.
5. **잔존의 쌍**: azure OS 디스크·gcp 부트 디스크가 VM 삭제 후 남는다 — CB
   드라이버가 디스크를 직접 지우던 이유의 실측 검증.
6. **sshKey 3사 완결**: aws 선택(동적) · azure 자원 있되 무참조 · gcp 자원 부재 —
   CB의 "필수"는 도구의 요구.
7. **검증 도구의 비균일**: preflight 깊이가 RP별(azure)·API별(aws DryRun)로 다르고
   gcp엔 상당물이 없다.
8. **참조 무결성이 자원 종류마다 다르다**: EKS 클러스터가 ACTIVE인데 IAM 역할의
   정책 분리가 **성공한다**. 네트워크 자원은 삭제 보호가 걸리는데 IAM은 안 걸린다.
   이 관측이 §4-2(기능 축)를 낳았고, 정작 이 사례 자체는 신호가 갈리지 않아
   **여전히 미판정**이다 — 축을 연 계기가 그 축에서 아직 안 닫힌 셈이다.
9. **쌍 호환은 사라지지 않고 옮겨간다**: azure Basic PIP 축은 신규 구독에서
   소멸했는데(한도 0), 그 자리에 AZ 게이트웨이↔zone PIP 축이 있었다.
10. **중립화 기제 5+1**: 드라이버 합성·절단·기제 치환·값 인라인·서버측 암묵
    (+교차 주입). **절단(azure SG `[0]`)은 tumblebug까지 무보정** — 중립화가
    정보를 잃는 실증.
11. **참조가 있다고 결속인 것이 아니다**: gcp 커스텀 이미지는 원본 디스크를
    지운 뒤에도 `sourceDisk` 필드가 **허상 참조로 남는다**. 스키마 후보가 곧
    주장이 아니라는 이 분석의 전제를 자원 층에서 보여주는 실물.
12. **KB 관측과 컨트롤 플레인이 갈린 자리**: graphkb에 `node→customImage`
    생명주기 결속이 있었지만 3사 모두 이미지 존재 중 원본 삭제를 허용했다.
    결속이 없으므로 lifecycle 행을 **만들지 않았다**(없는 결속은 적지 않는다).
13. **오류 문구가 원인을 가린다**: azure 스토리지 계정 생성이 `Microsoft.Storage`
    RP 미등록 상태에서 **`SubscriptionNotFound`**를 냈다. 구독이 없다는 뜻이
    아니었고, 이 오해가 k8s RWX 실패의 원인 판정을 한 라운드 지연시켰다.

## 7. 근거 관리 — 우리 구성과 약점

임의 설정은 전부 표시 + 기계 제약 + 위협 등재로 관리한다: 어휘 선정(Z1) ·
형태→질문 대응표(T1) · 이름/쌍 휴리스틱(Z3) · 기제 이름 · 실험→판정 배정표
(빌드가 실측 대조) · 술어 소비 분류 · 실험 보조 선택. 분류 불가 입력에는 죽는다.

**약점 8 (논문 위협 절 원고)**:
① aws `nic→subnet` required는 클라이언트 층 거부(서버 미도달).
② `holds`는 "그 상황에서 거부됐다"이지 "항상"이 아님(강제 삭제 미측정).
③ 단일 리전 · 대부분 단일 실행(AKS vnet 합성만 2회 재현).
④ **기능 축의 신호가 하나다** — 외부 TCP 도달성뿐이라, 그 신호로 안 보이는
   기능 상실(DNS 해석·NAT·인증)은 이 판정이 말하지 않는다. EKS IAM은 신호를
   못 찾아 미판정으로 남았다(§4-2).
⑤ **측정 깊이가 CSP·자원마다 다르다** — gcp Filestore는 존 자원 부족으로
   리전 내 존을 옮겨야 했고(교란), DNS는 사설 영역 한정이며(공인 미측정),
   VPN은 터널을 안 만들었다(상대편 장비 필요).
⑥ **기본 구성 판정** — k8s 합성은 애드온 0인 관리형 기본에서만 잰 것이다.
   컨트롤러·CSI를 깔면 답이 바뀐다(Ingress에서 실제로 그럴 것이다).
⑦ 하네스 결함이 측정을 가렸다가 잡힌 것이 **열 건 이상**이다. 신호 4종
   라운드에서만 다섯이 나왔다: 개인키 절단 2종(헬퍼 excerpt 600자 ·
   `--output text`) · 캐시 2종(DNS TTL+resolved · 페이지 캐시) · 파이프가
   종료 코드를 삼킴(`| tail -1`). 여기에 **결과 파일 경합**(겹쳐 띄운 셀이
   앞 결과를 덮어써 다른 VPC의 라우트를 지웠다)까지 더하면 여섯이다.
   전부 "측정이 아니라 도구가 틀린" 부류이고 판정으로 둔갑하기 쉬웠다 —
   **잡히지 않은 것이 없다고 말할 수는 없다.**
⑧ **환경 전제가 판정을 오염시킬 수 있다** — RP 미등록이 `SubscriptionNotFound`로
   표면화돼 한 라운드를 오판할 뻔했고(§5-13), 재측정으로만 갈렸다.

## 9. 남은 갈래

어휘 밖 대기열과 기능 축 첫 실험은 2026-07-31에 닫혔다(§4-2·§4-3). 남은 것:

- **상류 배선** — 요구사항·설계 에이전트가 `app/core/dependency` 문을 실제로
  부르게 한다(진실 문서 §10-2 접점). 분석이 시스템 가치가 되는 지점.
- **EKS IAM 기능 축** — 신호를 다시 정해야 한다. 조건: 동기 신호이거나,
  변이 상태를 비동기 완료까지 유지할 것(§4-2 말미).
- ~~기능 신호 다변화~~ **완료(2026-08-01)** — 7종(§4-2 표). 앱이 필요하다고
  본 둘 중 LB 서빙은 결국 **앱 없이** 됐고(python3 http.server가 OS 기본),
  서비스 디스커버리만 관측자 이미지를 썼다.

  **`loadBalancer→vm`은 기능 축이 새 간선을 연 첫 사례다** — LB는 백엔드
  없이도 만들어지므로 존재 축에서는 이 결속이 보이지 않는다. 기능 질문이
  없었다면 이 의존은 KB에 존재하지 않았을 것이다.
- **반복 측정** — 위협 ③. 판정을 바꿀 만한 흔들림은 아직 관측되지 않았지만
  (재현한 둘은 같은 결과), 반복 없이는 그렇게 말할 수 없다.

  참고: 같은 날 **에이전트 프로브**는 짝지은 반복(3회)을 돌렸다
  (`report/probe-repeat-2026-07-31/`, 저장소 밖). 영어 31/33·한국어 32/33이
  안정이고, 흔들린 짝(EN23↔X7)은 **양쪽 다** 흔들려 언어 효과가 아니다.
  의존성 실험의 반복은 이것과 별개로 남아 있다 — 클라우드 자원 생성이라
  비용·시간이 다르다.
