# 1부 — 이게 뭔가

## 1. 다섯 문장 요약

1. 클라우드에 프로그램을 올리려면 서버·네트워크·디스크 같은 **부품 수십 개**를
   순서대로, 서로 맞게 만들어야 합니다.
2. 그 규칙이 너무 많고 회사마다 달라서 사람이 못 외웁니다. 그래서 **AI에게** 시킵니다.
3. 그런데 AI는 **모르는 것도 자신 있게 지어냅니다.** "이 디스크는 최대 16TB입니다" —
   어제는 맞았고 오늘은 틀린 말을요.
4. 그래서 AI가 **참고할 사실 창고**를 따로 만들었습니다. 이게 이 지식베이스입니다.
5. 창고의 제1원칙은 "많이 아는 것"이 아니라 **"모르는 걸 안다고 하지 않는 것"**입니다.

## 2. 비유 하나로

**건축 자재상**을 생각하면 거의 맞습니다.

| 창고의 서랍 | 자재상으로 치면 | 답하는 질문 |
|---|---|---|
| 의존 그래프 | **조립 순서도** | "이걸 만들려면 뭐가 먼저 있어야 하나?" |
| 제약·한도 | **규격서** | "이 부품, 얼마까지 되나? 나중에 바꿀 수 있나?" |
| 가격 | **가격표** | "이거 얼마? 예약하면 싸지나?" |
| 성능 | **시험 성적서** | "얼마나 빠른가? 함정은 없나?" |
| 동반 부품 | **세트 구성표** | "이거 사면 뭐가 따라오나?" |
| 최소 규모 | **설치 요건표** | "이걸 돌리려면 최소 몇 명 자리가 필요한가?" |
| 환경 | **지도와 달력** | "어느 지역에 있나? 언제까지 지원되나?" |
| 설계 지침 | **선배의 조언집** | "이런 상황엔 보통 어떻게 하나?" — 사실이 아니라 조언 |
| 설계도 접수 | **주문서 창구** | 설계도를 받아 배치도와 견적을 낸다 |

자재상과 다른 점이 딱 하나 있습니다.

> 보통 자재상은 모르는 걸 물으면 얼버무립니다. **이 창고는 "그건 우리가 안 봤습니다"와
> "그건 정말 없습니다"를 다른 말로 답하도록** 만들어져 있습니다.

이 구분이 이 프로젝트 전체의 핵심입니다. 왜냐하면 —

```
"제약이 없습니다"   ← 확인했고, 없다
"우리가 안 봤습니다" ← 있을 수도 있다
```

둘을 똑같이 "아무 말 안 함"으로 처리하면, 사용자는 **위험한 설정을 안전하다고
믿습니다.** 실제로 이 창고가 한때 구글 리소스 527종 전부에 "제약 없음"이라고
답한 적이 있습니다 — 구글 데이터를 **읽지도 않은** 상태로요.

## 3. 답이 어떻게 생겼는지 — 실물 하나

말로만 하면 안 와닿으니 실제 답을 봅니다. 같은 질문, 조건만 다릅니다.

```
질문) AWS 디스크에 30,000 GiB 넣어도 되나? (디스크 종류 = gp2)
답)   안 됩니다. 30,000 GiB는 최대 16,384 GiB를 넘습니다
      (단, VolumeType='gp2'일 때. 공식 소스 두 곳에서 교차 확인)

질문) 같은 질문, 디스크 종류 = gp3
답)   됩니다.

질문) 같은 질문, 디스크 종류를 안 알려줌
답)   조건에 따라 갈립니다. 14가지 조건 중 9개는 허용, 5개는 불허.
```

세 번째가 이 창고의 성격을 보여 줍니다. **모르면 한쪽으로 찍지 않습니다.**
"아마 되겠죠"라고 하면 gp2 디스크를 망가뜨리고, "안 됩니다"라고 하면 gp3로 하면
되는 길을 막습니다. 그래서 **세 번째 상태**를 그대로 답합니다.

## 4. 사실에 붙는 두 개의 꼬리표

창고의 모든 사실 한 줄에는 **꼬리표 두 개**가 붙습니다. 이게 다른 지식베이스와
가장 다른 점입니다.

| 꼬리표 | 뜻 | 예 |
|---|---|---|
| **어디서 왔나**(evidence) | 어느 재료의 어느 부분에서 나온 사실인가 | `cfn-schema` = AWS 공식 스키마 |
| **어떻게 아나**(basis) | 셋 중 하나 | 아래 |

`basis`가 셋입니다 — **이 셋의 차이가 이 프로젝트의 학문적 핵심입니다.**

```
stated   (말했다)  원본에 그렇게 적혀 있다. 우리는 옮겼을 뿐이다
inferred (짐작했다) 이름·문장·구조를 보고 우리가 추측했다. 틀릴 수 있다
observed (세어봤다) 실제 사례 뭉치에서 몇 %인지 센 것. 규칙이 아니라 관찰이다
```

왜 이게 중요한가를 실물로 보면:

```
t3.micro  → "지속 성능 보장 안 됨"           (AWS가 직접 말한 것)
m5.large  → "지속 성능 보장됨 (이름 규칙에서 짐작)"  ← 괄호가 붙는다
```

뒤쪽에 괄호가 붙은 이유가 있습니다. AWS에는 "이 인스턴스는 버스트형인가?"라는 칸이
있는데, **`true`는 직접 말한 것이고 `false`는 "그 칸에서 빠졌다"는 뜻일 뿐**입니다.
실제로 `t1.micro`가 `false`인데 t1은 버스트형입니다 — 크레딧 제도보다 **앞선
세대**라 그 칸에서 제외됐을 뿐이거든요. 그대로 옮겼다면 "t1은 성능이 보장된다"는
**정반대 답**이 나갔을 겁니다.

> **한 방향만 말하는 칸을 양방향으로 읽으면 안 된다.** 이걸 지키느라 29,395건이
> `stated`에서 `inferred`로 내려갔습니다.

## 5. 침묵도 다섯 종류다

"모릅니다"에도 종류가 있고, 각각 다른 문장으로 답합니다.

| 상황 | 실제 답변 | 사용자가 해야 할 일 |
|---|---|---|
| 봤는데 제약이 없다 | "알려진 제약 없음 — **수집 범위 안이므로 '없음'이 답**" | 그대로 진행 |
| 아예 안 봤다 | "**수집 범위 밖**이라 모릅니다 — 없다는 뜻이 아닙니다" | 직접 확인 |
| 있는데 못 읽었다 | "제약은 있으나 그 정규식을 우리가 못 읽습니다" + 원문 | 원문 읽기 |
| 조건에 안 걸린다 | "조건부 제약 938건 중 **주신 조합에 걸리는 것이 없습니다**" | 오타 의심 |
| 그 회사는 추적 안 함 | "ncp는 성능 데이터를 추적하지 않습니다(aws/azure/gcp/ibm만)" | 다른 곳 |

옛날에는 이 다섯이 **전부 같은 출력**이었습니다 — 함수가 넷 다 `None`을 반환해서
화면에 나오는 글자가 **바이트 단위로 똑같았습니다.** 검증된 안전한 인스턴스와
우리가 아무것도 모르는 인스턴스가 구별이 안 됐다는 뜻입니다.

## 6. 축×클라우드 커버리지 — 한 표로

"12개 클라우드를 지원한다"는 말이 **축마다 다른 뜻**입니다. 실제로 센 값입니다.

   부품 목록만 있고 **부품 사이의 관계가 0건**입니다. 즉 "이걸 만들려면 뭐가 먼저
   필요한가?"에 답할 수 있는 곳은 AWS·Azure·GCP뿐입니다. 나머지는 부품 이름과
   규격만 압니다. — 결함이 아니라 **아직 안 만든 축**이고, 이렇게 적어 두지 않으면
   "12개 클라우드 그래프"가 12곳 전부에서 관계를 답한다는 뜻으로 읽힙니다.
2. **Oracle이 가장 오해하기 쉽습니다.** 규격이 14,614건(3위)이나 있는데 가격도
   성능도 관계도 0입니다.
3. **AWS는 할인가가 없습니다.** 예약·약정 가격 조합이 너무 커서 일부러 안 담고,
   대신 답변에 이유를 밝힙니다.
4. **국내 클라우드는 전 축에서 1% 미만입니다.** 공개된 기계 판독 자료가 그만큼밖에
   없기 때문입니다. 이 창고로 "국내 클라우드 가이드라인"을 주장하면 안 됩니다.

## 7. 못 하는 것 — 일부러 안 하는 것들

유혹이 컸지만 **근거가 없어서 안 하는 것들**입니다. 이게 이 창고의 성격을
가장 잘 보여 줍니다.

| 안 하는 것 | 왜 |
|---|---|
| "동접 1만이면 서버 몇 대?" | 그 답의 근거가 될 **공개 자료가 없습니다.** 근거 없는 규모 산정은 확신에 찬 오답의 왕도입니다 |
| 총 비용 합계 | 일부 항목만 값을 아는데 합계를 내면 **그럴듯한 거짓 총액**이 됩니다. 대신 "축별로 나눠서 + 모르는 것 N건" |
| "A와 B 중 뭐가 빠른가" 승자 선언 | 워크로드에 따라 갈립니다. 지속 대역폭은 t3가 높고 최대 버스트는 m5가 높은데, **한 줄로 접으면 어느 쪽으로 접든 거짓** |
| 클라우드 회사 간 성능 비교 | 잣대가 다릅니다(ACU는 Azure에만, 클럭은 AWS에만). 구조적으로 막아 뒀습니다 |
| "데이터는 한국에" 준수 판정 | **법적 판단**이라 우리가 못 합니다. 리전 사실과 대조만 하고 "판정 불가"를 명시합니다 |
| 컴퓨트 방식(VM/k8s/서버리스) 임의 선택 | **상충 없는 후보가 정확히 하나일 때만** 권고합니다. 여럿이면 안 고릅니다 |

## 8. 그래서 신뢰도가 어떻게 되나 — 정직한 요약

| | |
|---|---|
| **믿어도 되는 것** | 규격·한도 값(공식 스키마 출처), 조건이 붙은 판정, 정가, "모른다"는 답 |
| **꼬리표를 보고 믿을 것** | 부품 간 관계 — Azure VM은 **94%가 이름 추론**, AWS EC2는 3%뿐. 같은 기능인데 소스가 달라서 신뢰도가 다릅니다. 답에 그 비율이 적혀 나옵니다 |
| **참고만 할 것** | 설계 지침(조언이지 사실 아님), 동시 출현 통계(사례 뭉치에서 센 것이지 규칙 아님) |
| **못 믿을 것** | 표에 없는 클라우드·축. "지원"이 곧 "답할 수 있음"이 아닙니다 |

# 3부 — 재료 47가지 전부

여기가 이 문서의 본체입니다. **하나도 빠짐없이** 설명합니다.

## 읽는 법

각 재료는 이렇게 적습니다.

- **받는 곳** — 실제로 받아 오는 URL **그대로**입니다. 등록부(`kbcommon/sources.py`)에
  적힌 것을 옮겼고, 손대지 않았습니다. 대부분 **버전이 URL 안에 이미 박혀
  있습니다** — 그래서 이 주소를 브라우저에 그대로 붙여 넣으면 우리가 쓴 것과 **같은
  파일**이 나옵니다(지문 핀 5종만 예외).
- **못 박기(핀)** — 언제 것인지 고정하는 방법. `태그`/`커밋`/**`지문`**/`동봉`
  - **`지문`이 붙은 5개는 재현이 원리적으로 불가능합니다.** 버전 개념이 없는
    소스라 받은 파일의 sha256만 남깁니다. 재현은 못 해도 **바뀐 건 압니다.**
- **라이선스** — 등록부에 적힌 것만 씁니다. **"기록 없음"은 "자유롭다"가 아니라
  "우리가 아직 확인 안 했다"**입니다(13종). 짐작해서 채우지 않았습니다.

전체 분포: 태그 23 · 커밋 18 · **지문 5** · 동봉 1.

### 주소를 보면 받는 방식이 보입니다

URL 모양이 다섯 가지뿐이라, 주소만 봐도 어떻게 받는지 알 수 있습니다.

| 주소 모양 | 받는 방식 | 예 |
|---|---|---|
| `raw.githubusercontent.com/…/<태그나 커밋>/…` | **파일 하나**를 그대로 내려받음 | 대부분의 소스 |
| `codeload.github.com/…/tar.gz/…` | **저장소 통째로** tar.gz (수 MB~326MB) — 받아서 안에서 필요한 파일만 읽음 | Terraform provider 계열, 템플릿 코퍼스 |
| `files.pythonhosted.org/…/*.whl` | **파이썬 패키지(zip)** — 경로에 해시가 박혀 있어 내용이 불변 | `cfn-lint` |
| 회사 API 주소 (`prices.azure.com`, `globalcatalog.cloud.ibm.com`, `pricing.us-east-1.amazonaws.com`) | **살아 있는 API를 호출** — 자격증명 없이 응답이 옵니다 | 가격·카탈로그 3종 |
| 그 밖 (`schema.cloudformation…zip`, `cloud.google.com/…`, `docs.aws.amazon.com/pdfs/…`) | 회사가 직접 서빙하는 zip·웹페이지·PDF | 지문 핀 소스들 |

`cb-spider-map` 하나만 URL이 아니라 **저장소 안의 파일 경로**입니다
(`graphkb/parsers/core_vendor_map.json`) — 사람이 손으로 고치는 표라서요.

### 직접 받아 보려면

받는 일은 `kbcommon/fetch.py`가 전부 합니다. 알아 둘 것은 셋입니다.

1. **캐시된다.** 같은 파일을 여러 축이 쓰므로 한 번만 받습니다. 위치는
   `CLOUDKB_CACHE_DIR` 환경변수, 없으면 `app/core/cloudkb/.cache/cloudkb/`.
   받다가 끊겨도 캐시가 오염되지 않게 임시 파일에 쓴 뒤 통째로 바꿔치기합니다.
2. **받은 것마다 기록이 남는다.** 파일 옆에 `<파일명>.provenance.json`이 생기고
   URL·sha256·크기·받은 시각·서버가 알려 준 `Last-Modified`/`ETag`가 들어갑니다.
   등록부의 핀이 **"무엇을 받기로 했나"**라면 이 파일은 **"실제로 무엇을
   받았나"**입니다. 둘이 짝입니다.
3. **재현이 필요하면 파일을 직접 넘길 수 있다.** 지문 핀 소스는 나중에 같은 것을
   다시 받을 수 없으므로, 받아 둔 파일을 보관해 뒀다가 빌드할 때 `--source-file`로
   넘기면 그때 그 파일로 다시 만들 수 있습니다.

> **왜 이 기록을 만들었나**: 감사 중에 캐시된 AWS zip(2,783,390 B)이 같은 URL의
> 라이브(2,794,161 B)와 **이미 달라진 것**을 발견했습니다. 그 순간 산출물이 어느
> 입력에서 나왔는지 알 방법이 없어졌습니다. 고정할 수 없는 소스라도 **무엇을
> 썼는지는 기록할 수 있습니다.**

## B. 회사가 기계에 주라고 만든 설명서 (8종)

**사람이 읽는 문서를 긁지 않는다**는 것이 이 창고의 원칙입니다. 회사의 배포
시스템이 실제로 쓰는 스키마를 씁니다 — **틀리면 그 회사가 먼저 아프기** 때문입니다.

**8. `cfn-schema`** — AWS 리소스 스키마 ★최대 기여 소스

  여기서 나옵니다.
- **가장 큰 약점**: AWS가 **같은 URL에 zip 하나를 계속 덮어씁니다.** 버전도 태그도
  아카이브도 없습니다. 즉 **이 창고 최대의 근거가 재현 불가능**합니다.
- 실측된 증거: 재빌드했을 때 고정된 소스는 결과가 완전히 같았고 **AWS만**

- 받는 곳: `https://schema.cloudformation.us-east-1.amazonaws.com/CloudformationSchema.zip`
- 핀: **지문(고정 불가)** · 라이선스: **기록 없음** ← 저장소가 없어 라이선스 문서 자체가 없음

# 5부 — 한 장으로 줄이면

만든 사람이 아니라 **읽는 사람**이 기억할 것입니다.

1. 이건 **AI가 클라우드 질문에 지어내지 않도록** 옆에 두는 사실 창고다.
2. 사실 한 줄마다 **어디서 왔는지**와 **어떻게 아는지**가 붙어 있다.
3. **"모른다"에 다섯 종류**가 있고, 다섯 개의 다른 문장으로 답한다.
4. 조건이 갈리는 값은 **조건과 함께** 답하고, 조건을 모르면 **3상태**로 답한다.
5. 부분만 아는 값들의 **합계는 내지 않는다.** 모르는 것을 0으로 치지 않는다.
6. **재료는 47가지**이고, 그중 5가지는 재현 불가능하며, 13가지는 라이선스가 아직
   확인 안 됐다 — 그 사실도 이 문서에 적혀 있다.
7. **12개 클라우드는 축마다 다른 뜻**이다. 6절의 표가 진짜 지도다.
8. 이 창고의 자랑은 아는 게 많은 것이 아니라, **모르는 걸 모른다고 말하는 것**이다.
