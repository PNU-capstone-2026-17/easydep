# 관심사 도출 클린룸 재현 실험 (2026-08-02)

> 계기: 사용자 질문 — 실측 재도출(같은 날, `concern-rederivation-2026-08-02.md`)의
> 군집·질문문은 구 29건을 아는 상태에서 작성됐다(T-사후 정당화). 이를 재려고
> **이전 컨텍스트가 없는 서브에이전트**에게 같은 도출을 시켰다.

## 1. 실험 설계

피험 에이전트에게 준 것: 메타 특성 원문 · "근거는 실측만" 규율 · claims.json
사본(스크래치패드 — 저장소 접근 금지 지시) · perfkb 실측 한 줄(버스트 37/100).
**주지 않은 것**: 우리 부류 필터(대체·합성·잔존·동반 정리·무방비) · 군집 7개 ·
질문문 · 좌표 유일성 규칙 · 관심사 개수에 대한 어떤 힌트.

## 2. 결과 요약 — 규칙·집합은 수렴, 군집은 갈림

| 축 | 본 도출 (7건) | 클린룸 (13건) | 판정 |
|---|---|---|---|
| 도출 규칙 | 침묵을 채우는 부류만, 거부 제외 | **"침묵 치환 검사"** — (a) 소리 내어 거부 vs (b) 침묵 대체, (b)만 채택. 부류 5개가 사실상 동일 | **수렴** |
| 입장 좌표 | 53 + perfkb | 54 (지어낸 좌표 **0**) — 대부분 겹침 | **수렴** |
| 탈락 부류 | 거부·보호 계열 | 거부·배치/쌍호환 조건·삭제 보호·**무데이터 동반 정리**·미관측 optional·양상 반전 자체·방법론 메타 관측 | **수렴 + 세분** |
| 군집 입도 | 7 | 13 | **갈림** |
| 좌표 배정 | 유일 (강제) | 12건 이중 인용 (규칙 안 줌) | 구조 차이 |

**해석**: T-사후 정당화 위협이 정확히 국소화됐다 — "무엇이 들어오는가"(규칙·
집합)는 독립 재현이 수렴해 기억 재생이 아님을 지지하고, "어떻게 묶는가"(군집)는
두 실행이 갈려 **우리 구성이라는 표시가 실증**됐다.

## 3. 군집 대응표

| 클린룸 13 | 본 도출 7 대응 |
|---|---|
| ① 어느 네트워크에서 도는가 | network-isolation (거의 동일 집합) |
| ② 트래픽 필터 규칙 | reachability + protection의 일부(기능 좌표 이중 인용) |
| ③ 인터넷 연결(IGW) | protection에서 **분리** |
| ④ 노출 기제(Service/Ingress) | platform-owned의 일부를 노출 축으로 재배치 |
| ⑤ 내부/공개 스킴 | reachability의 스킴 절반 |
| ⑥ 어떤 신원으로 도는가 | cloud-api-access의 존재 절반 |
| ⑦ 권한 집합(이연 실패) | cloud-api-access에서 **분리** — 빈 역할 ACTIVE→join 실패 관측을 별도 결정으로 |
| ⑧ 저장 프로비저닝 | platform-owned의 PVC 절반 + aws SC 미지정 방치 |
| ⑨ 볼륨 데이터 수명(reclaim Delete) | data-fate의 소멸 절반 |
| ⑩ 잔존물 정리 책임 | data-fate의 잔존 절반 |
| ⑪ **주소 안정성** | **대응 없음 — 본 도출이 놓친 후보** (회복 주소 3사 3색: gcp 새 주소 ↔ aws/azure 같은 주소, 기능 축 회복 관측에서) |
| ⑫ 연속성 무방비 (우산) | runtime-binding-protection (기능 15 전량 — 개별 관심사와 이중 인용) |
| ⑬ 용량·기종 | load-shape + platform-owned의 default-pool |

## 4. 클린룸이 낸 개선 후보 둘

1. **주소 안정성 관심사**: 회복 관측(gcp 임시 IP는 재부여 시 새 주소, aws EIP·
   azure PIP는 같은 주소)이 "엔드포인트 주소가 바뀌어도 되는가"라는 요구사항
   결정을 지지한다. 본 도출은 이 좌표들을 protection에만 넣어 이 결정을 못 봤다.
2. **무데이터 동반 정리의 축출**: Service→LB lifecycle(3사)은 데이터·비용이 걸린
   침묵 결정이 없다(합성물의 대칭 정리 — 계획층 지식). 본 도출의 data-fate가
   이들을 포함한 것보다 정교한 판정이다.

편차 하나: ⑦이 required 주장(aws/k8sCluster→iamRole/existence)을 인용 — 규칙
위반이나, "빈 역할도 통과"라는 침묵 관측을 나르는 좌표라는 정당화가 붙어 있다.

## 5. 한계

- 클린룸도 같은 모델 계열이다 — 사람 재현이 아니라 **모델 내 재현**이고, 훈련
  분포가 공유된다. 군집 갈림이 나온 것이 오히려 이 한계가 결정적이지 않다는
  신호이지만, 규칙 수렴을 "필연"으로 읽으면 안 된다.
- 1회 실행이다. 군집 입도의 분포(7~13 사이 어디로 수렴하는가)는 반복이 필요하다.
- 프롬프트가 메타 특성을 줬다 — 메타 특성 자체의 타당성은 이 실험 밖이다.
