# 비교실험 계획 — 시스템 산출 vs 베이스라인 (2026-08-02, 실행 전)

> 사용자 결정 둘: ① 계약은 신규 앱 개발 전제(existingResources 제거) ② 비교
> 대상은 **단순 LLM 및 MetaGPT류 프레임워크**. 이 문서는 실행 전 계획이다 —
> 완료는 커밋이 기록한다.

## 1. 무엇을 비교하나

같은 입력(예시 CNA의 요구사항 산문 + 클라우드 제약 산문)을 세 계열에 주고
**클라우드 배포 산출물**(계획·매니페스트·질문·경고)을 비교한다:

| 계열 | 구성 |
|---|---|
| A 본 시스템 | 요구사항 에이전트 → 설계 → 계획(실측 사영) → 매니페스트 + 점검표 |
| B 단순 LLM | 같은 급 모델, 단발 프롬프트("이 요구사항으로 배포 구성을 만들어라") |
| C 프레임워크 | MetaGPT 등 공개 멀티에이전트 프레임워크의 기본 파이프라인 |

## 2. 심판 — 자기 KB로 채점하지 않는다 (T-자기 심판)

우리 depkb 검사기로 B·C를 채점하면 **자기 기준 채점**이다(우리 어휘·우리
판정으로 남을 재는 것). 심판은 중립층에 둔다:

1. **컨트롤 플레인** — 산출 매니페스트/IaC를 실제로 apply: 거부 수·거부 지점.
   (거부·성공 판정 규율은 depkb 실험 규율 그대로 — CLI는 오라클이 아니다.)
2. **실배포 후 기능 신호** — 배포가 선 경우, 신호 7종(도달성·서빙·발견·볼륨
   I/O·자격증명·이름 해석·join)의 실제 통과 여부. 신호 자체는 클라우드 중립
   관측(외부 TCP·HTTP 200 등)이라 심판 자격이 있다.
3. **보조(비중립 명시)**: 근거 추적성(주장에 좌표가 붙는가) · 모르는 것의 처리
   (질문/인계로 내는가, 지어내는가) · 비용 예측의 존재와 실측 대비 오차.
   이 축들은 우리 가치 기준이라 **비중립임을 표시하고 따로 센다.**

## 3. 예시 CNA — 관심사 8건이 전부 걸리는 최소 구성

신규 개발 전제. 관심사 축의 결정들이 실제로 걸려야 비교가 의미를 갖는다:

- **API 컴포넌트** (외부 노출 — 노출 경로·도달성·주소 안정성·부하 모양)
- **내부 서비스 1** (service-discovery가 걸릴 내부 호출)
- **영속 저장** (PVC — 저장 프로비저닝·데이터 운명)
- **클라우드 API 호출 지점** (권한 축 — 예: 객체 저장이 아니라 어휘 안에서,
  인스턴스 메타데이터/디스크 조작 수준으로 소박하게)
- 요구사항 산문·제약 산문은 우리 입력 형식으로 새로 쓴다. **코퍼스 함정을
  피해 쓰지 않는다** — 실제 사용자가 쓸 법한 문장으로 쓰고, 그것이 세 계열
  모두에 공정한 입력이 되게 한다.

**경계(기존 결정 유지)**: 이 앱은 claims의 측정 기준이 아니다 — 의존 주장의
오라클은 컨트롤 플레인이고, 앱은 사슬 시연·비교의 재료다.

## 4. 단계

- **P1** 이 계획의 확정 + 예시 CNA 요구사항·제약 산문 작성
- **P2** 앱 구현(컨테이너 2~3개, 최소 코드) + 수동 검증(로컬에서 돈다)
- **P3** 계열 A 완주(요구사항→매니페스트) · B/C 산출 수집(같은 입력, 프롬프트
  공정성 기록)
- **P4** 심판 실행 — apply + 기능 신호(비용 규율: azure 우선, 다른 CSP는 예산
  확인 후) · 보조 축 채점(비중립 표시)
- **P5** 기록·원고 반영

## 5. 위협 (실행 전에 적는다)

- **T-자기 심판**: §2로 완화하되, 보조 축은 완화 불가 — 비중립 표시로만.
- **T-프롬프트 공정성**: B에게 얼마나 친절한 프롬프트를 주느냐가 결과를
  좌우한다. 완화: B 프롬프트에 동일 입력 전문 + 산출 형식 명세까지 주고,
  프롬프트 원문을 기록에 포함. 여러 강도(무힌트/형식 힌트)로 나눠 잴 수 있다.
- **T-단일 표본**: 앱 하나로는 일반화 불가 — "이 앱에서 이랬다"까지만 주장.
- **T-프레임워크 버전**: C는 버전·설정에 민감 — 핀 기록.
- **T-실행자 편향**: 세 계열 실행·채점을 같은 사람이(우리가) 한다.
  프로토콜(입력·프롬프트·판정 기준)을 실행 전에 이 문서로 고정하는 것이 완화.
