# 남은 라운드 계획 — VPN 3사 · Filestore 양성 · EKS IAM 기능축 (2026-07-31, 실행 전)

"다 하자"(사용자). 선택 사항으로 미뤄 뒀던 것 전부. 비용이 드는 셋을
한 문서에 묶는다.

## 1. VPN 3사 완결

azure만 4층 완주였고(이름 조건 GatewaySubnet·zone 쌍 호환까지) aws·gcp는
미측정이라 계획을 안 냈다. 여기서 존재·생명주기를 잰다.

| CSP | 사다리 |
| --- | --- |
| aws | A1 허상 VPC로 VPN GW attach 거부 · A2 VPN GW 생성(무료 — attach 전) · A3 VPC에 attach(양성) · L1 attach 상태에서 VPC 삭제 시도 · 정리 |
| gcp | A1 network 없이 VPN GW 거부 · A2 전용 network로 생성(양성) · L1 GW 존재 중 network 삭제 시도 · 정리 |

**터널·고객 게이트웨이는 만들지 않는다** — 우리 어휘는 `vpn→network/
subnet/publicIp`이고 터널은 상대편 장비가 있어야 한다(범위 밖으로 명시).
aws VPN GW는 attach 전에는 과금되지 않고, attach 후 시간당 $0.05다.

## 2. gcp Filestore 양성 대조

dns·fs 라운드에서 거부 층까지만 쟀다(최소 티어 1TiB 비용 규율). 그
한계를 없앤다: BASIC_HDD 1TiB를 **실제로 만들고 즉시 지운다**(~10분,
시간당 약 $0.22 → 실비 $0.04 수준). 관측: network 참조 실물 · 생성 후
network 삭제 시도(생명주기).

## 3. EKS IAM 기능 축 — 신호 정의가 본체

기능 의존 1라운드에서 "EKS 클러스터가 ACTIVE인데 역할 정책 분리가
성공"을 관측만 하고 판정을 미뤘다. **무엇이 깨지는지 신호를 정하지
못했기 때문**이다. 여기서 신호를 정한다:

> **신호: 새 노드그룹 생성이 성공하는가.** EKS 컨트롤 플레인은 클러스터
> 역할로 EC2·ENI를 조작한다. 정책을 떼면 그 조작이 막혀야 한다.

이 신호를 고른 이유: (a) 외부에서 API 하나로 관측되고 (b) 실패하면 EC2가
안 뜨므로 비용이 거의 없고 (c) 성공/실패가 이분법이다.

사다리: 클러스터 ACTIVE → **정책 분리(성공 = 무방비)** → 노드그룹 생성
시도(기능 신호) → 정책 재부착 → 노드그룹 생성 재시도(회복) → 정리.

**회복 셀에서 노드그룹이 실제로 만들어지면 EC2가 뜬다** — 즉시 삭제한다.
회복이 CREATING까지만 가도 판정에는 충분하다(거부가 아니라는 것이 신호).

위협: 정책 분리의 전파 지연 — 실패 관측을 연속 2회로 강화한다. IAM은
결과적 일관성이라 지연이 길 수 있고, 그때는 미판정으로 적는다.
