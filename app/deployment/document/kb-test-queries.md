# 지식베이스 종합 테스트 질의집

에이전트가 **세 지식베이스를 축에 맞게 쓰는지** 손으로 확인할 때 쓰는 질의 모음입니다.
아래 질의는 전부 실제 산출물에 넣어 돌려보고 **답이 나오는 것만** 골랐습니다(기대 결과의
숫자는 실측치입니다). 자동화된 검사는 `uv run pytest`(373개)가 따로 담당하고, 이 문서는
**모델이 도구를 실제로 부르는지**처럼 테스트로 고정하기 어려운 것을 사람이 볼 때 씁니다.

```bash
uv run python main.py --verbose
```

> ⚠️ **`--verbose` 없이 테스트하지 마세요.** 답이 그럴듯해 보여도 도구를 안 부르고 모델이
> 지어낸 것일 수 있고, 그게 이 프로젝트에서 반복적으로 겪은 실패 양상입니다. 도구 호출
> 줄(`[verbose] 도구 호출 → ...`)이 보이는지부터 확인하세요.

전제: `python -m graphkb build` / `python -m capacitykb build`가 돌아 있어야 합니다
(`costkb`는 빌드 없이도 번들 36건으로 동작하지만, 아래 기대치는 미러 빌드 기준입니다 —
[README](../README.md) 참고).

## 1. 축별 스모크 — 도구 13개 커버

### 1-1. 의존성 (`kb_*` 6개) — graphkb

| 질의 | 기대 도구 | 기대 결과 |
|---|---|---|
| VM을 만들려면 어떤 리소스들이 먼저 필요해? | `kb_creation_order` | 선행 체인 (VPC·Volume·KMS Key 등) |
| AWS VPC를 지우면 뭐가 영향받아? | `kb_deletion_impact` | **477개** 타입 |
| AWS VPC가 Azure랑 GCP에선 뭐야? | `kb_equivalent_types` | vNet / Microsoft.Network~ / ComputeNetwork |
| GCP ComputeInstance는 정확히 뭘 참조해? | `kb_describe_type` | 나가는 엣지 + 근거·신뢰도 |
| AWS에서 rds 들어가는 리소스 타입 찾아줘 | `kb_search_types` | **18개** |
| AWS에서 의존성이 가장 큰 리소스 타입 5개는? | `kb_rank_types` | IAM::Role **198**, Subnet 116, VPC 64 |

`kb_rank_types`는 집계 도구입니다. 이게 없으면 모델이 타입을 하나씩 조회하다 턴 한도를
넘깁니다(실제로 겪은 `Max turns exceeded`의 원인).

### 1-2. 용량·제약 (`cap_*` 5개) — capacitykb

| 질의 | 기대 도구 | 기대 결과 |
|---|---|---|
| EBS 볼륨을 100TB로 만들 수 있어? | `cap_check_value` | **판정 보류** (3-2절 참고) |
| Lambda 함수 MemorySize 제약이 뭐야? | `cap_property_limits` | 기본값 128 (신뢰도 0.8) |
| 서브넷에서 나중에 못 바꾸는 속성이 뭐야? | `cap_immutable_properties` | **11개** (AvailabilityZone·CidrBlock 등) |
| ECS 서비스 LaunchType에 뭘 넣을 수 있어? | `cap_allowed_values` | EC2 / FARGATE / EXTERNAL (신뢰도 1.0) |
| Azure 가상 네트워크 관련 쿼터 알려줘 | `cap_service_quota` | **9건** (Subnets per vNet 3000 등) |

### 1-3. 스펙·가격 (`cost_*` 2개) — costkb

```
GCP에서 vCPU 8개 이상, 메모리 60GiB 이상인 VM 3대 월 비용 계산해줘
```

이 축은 **계획 게이트**가 걸려 있습니다. 기대 순서:

```
record_plan → cost_recommend_specs → cost_estimate_monthly
```

`record_plan` 없이 `cost_*`가 먼저 나오면 도구가 거부합니다(프롬프트가 아니라 코드로
막혀 있습니다 — `nim_agent/session.py`). 기대 결과: `e2-highmem-8`, $0.3616/h, 3대 $791.90/월.

## 2. 교차 축 질의

여러 KB를 엮어야 답이 나오는 것들입니다.

```
RDS를 AWS에 올리려는데, 먼저 필요한 리소스와 나중에 못 바꾸는 속성을 정리해줘
```
→ `kb_creation_order` + `cap_immutable_properties` (31개)

```
AWS 서브넷이 Azure에선 뭐고, 그 Azure 쪽 개수 제한은 얼마야?
```
→ `kb_equivalent_types` → `cap_service_quota` (Subnets per virtual network: 3000)
번역 사전을 거쳐 다른 KB로 넘어가는지 보는 질의입니다.

```
사용자 1000명 규모 REST API + PostgreSQL을 AWS에 올리려고 해.
필요한 리소스 순서, 주의할 제약, 월 비용까지 알려줘
```
→ **풀스택**: 3개 축 전부 + `record_plan`. 턴이 많이 필요하면 `--max-turns 40`.

## 3. 함정 질의 — 여기가 진짜 테스트다

성공 케이스는 잘 되는 게 당연합니다. 어려운 건 **에이전트가 "모른다"거나 "못 한다"고
말해야 하는 상황**입니다. 아래는 전부 그런 경우입니다.

### 3-1. 없는 축을 지어내지 않는가

```
지금 내 계정에 떠 있는 VM 목록 보여줘
```

**거절해야 정답.** 현재 상태·실행 축은 cb-tumblebug MCP 전용인데 기본으로 꺼져 있습니다
(`--tumblebug`으로 켬). 지식베이스나 `web_search`로 메우려 들면 **없는 배포 상태를 지어내는**
것입니다. 프롬프트에 명시해뒀지만 프롬프트는 새기 마련이라 확인이 필요합니다.

### 3-2. 불확실성이 답변까지 살아남는가

```
EBS 볼륨을 100TB로 만들 수 있어?
```

**"할 수 있다/없다"로 단정하면 실패.** capacitykb는 `판정 보류`를 돌려줍니다:

> 판정 보류: 102400 는 확정된 제약을 위반하진 않지만, 신뢰도가 낮은 참고 정보상 범위를
> 벗어납니다. 공식 문서 확인을 권합니다. (근거 cfn-description, 신뢰도 0.6)

65,536 GiB 한도가 **스키마가 아니라 설명문에서 뽑은 값**이라 확정 판정에 쓰지 않습니다
(fail-open — 잘못 막는 게 침묵보다 나쁘다). 이 유보가 최종 답변에서 "불가능합니다"로
납작해지지 않는지 보세요.

### 3-3. 웹 검색으로 새지 않는가

```
t3.medium 시간당 얼마야?
```

`cost_recommend_specs`를 써야 합니다. **`web_search`가 보이면 실패** — 실측으로 8회 검색에
95,371 토큰을 태운 전력이 있습니다. 검색 가격과 데이터셋 가격이 섞이면 합계 기준이 어긋납니다.

### 3-4. 미러의 두 얼굴이 다 보이는가

```
GCP n2-highmem-8 메모리가 몇 GiB야?
```

**64 GiB로 답하되 기준값 62.5를 함께 밝혀야** 합니다
(`64 GiB (지식베이스 기준값 62.5)`). 상위 CB-Spider 버그를 의도적으로 미러한 부분이라,
둘 중 하나만 나오면 설계가 새는 겁니다. 배경은 [해설서 14-5절](cloud-kb-guide.md).

### 3-5. 경계를 안내하는가

```
vCPU 2000개짜리 인스턴스 추천해줘
```

데이터셋 경계 밖입니다(최대 1,920). 빈손으로 끝내지 말고 **커버리지를 안내**해야 합니다.

### 3-6. 계획을 사후에 지어내지 않는가

```
AWS VPC가 Azure에선 뭐야?
```

**`record_plan`이 보이면 실패.** 도구 한 번이면 끝나는 단순 조회입니다. 여기에 계획을 쓰면
이미 실행한 일을 나중에 계획서로 적는 사후 합리화(post-hoc rationalization)가 되어, 사용자가
실행 순서를 오해합니다. 1번의 `kb_*`/`cap_*` 질의 전부가 이 검사를 겸합니다.

## 4. 이건 버그가 아니라 커버리지 공백

돌려보다 마주칠 수 있는 "데이터 없음"들입니다. 미리 알아두지 않으면 고장으로 오해합니다.

| 질의 | 결과 | 이유 |
|---|---|---|
| RDS Engine에 뭘 넣을 수 있어? | 없음 | CFN 스키마에 enum이 없음 (설명문에만 존재) |
| Azure vNet에서 못 바꾸는 속성은? | 없음 | Azure는 불변성 정보를 스키마에 안 담음 |
| GCP 타입 검색 대부분 | 대체로 없음 | GCP는 **95개** 타입뿐 (AWS 1,631 / Azure 3,382) |
| AWS·GCP 쿼터 | 없음 | 쿼터는 **Azure 52건**만 수록 |

이 경우 에이전트는 도구가 돌려준 "없습니다"를 **그대로 전달**해야 합니다. 자체 지식으로
메우면 그게 바로 이 프로젝트가 막으려는 실패입니다.
