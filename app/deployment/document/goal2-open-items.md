# 조사 1 — 각 축의 데이터를 어떻게 연결하나

## 결론

**새 소스도 새 손표도 필요 없습니다. 다리는 이미 데이터 안에 있습니다.**
이 프로젝트에서 네 번 반복된 그 교훈이 다섯 번째로 나왔습니다 — *이미 받아 둔 것의
안 쓰는 부분부터.*

```
번들 멤버   aws::AWS::EC2::Instance
   ↓  mapping-graph   equivalent_to (역방향)          근거 cb-spider-driver
core::vm
   ↓  core-graph      references via specId (required) 근거 swagger-field
core::spec
   ↓  =  costkb 스펙 카탈로그의 바로 그것              aws+us-east-1+m5.large
hourlyUSD   +   perfkb 성능 경고
```

## 실측 — 어디는 이미 붙어 있고 어디가 갈라져 있나

**타입 층 안에서는 거의 완전히 붙어 있습니다.**

```
번들 멤버 787종
   graphkb 노드에 있음      783   99.5%
   capacitykb 제약이 있음   767   97.5%
```

즉 "이 번들의 멤버가 무엇을 참조하고 어떤 제약을 갖나"는 **지금도 답할 수
있습니다.** 안 하고 있을 뿐입니다.

**사이징 ↔ 비용은 이미 조인됩니다.**

```
sizingkb reference_point 18건은 metric=specId, 값이 costkb id 그대로다
   workload:llm-bench  →  aws+us-west-2+g6e.2xlarge
   costkb id와 정확 일치  18 / 18  (100%)
```

**갈라진 곳은 하나뿐입니다 — 타입 층(번들·그래프·제약)과 스펙 층(비용·성능).**

```
번들 멤버 787종 중 mapping-graph에 걸리는 것   19종
```

19종밖에 안 되는 건 결함이 아니라 **mapping-graph가 core 개념 13종만 다루기
때문**입니다(vNet·subnet·vm·spec·nlb·k8sCluster 등 × 벤더 9곳 = 엣지 82).
그리고 **다리에 필요한 건 그 13종뿐입니다** — 나머지 768종은 애초에 시간당 단가가
붙는 물건이 아닙니다.

## 막는 것은 조인 키가 아니라 **가격의 부재**입니다

다리가 이어 주는 것은 **VM 하나**입니다. 번들의 나머지 멤버 — NIC·서브넷·라우트
테이블·로드밸런서·디스크 — 는 **가격 데이터가 아예 없습니다**(항목 5의 "스토리지·
관리형 서비스 0건"과 같은 구멍입니다).

그래서 **"번들 총비용"은 지금 데이터로 낼 수 없습니다.** 낼 수 있는 것은
*"VM 단가 + 값을 매길 수 없는 멤버 N종"*입니다.

이걸 총액처럼 내면 이 프로젝트가 가장 경계하는 실패입니다 — **모르는 것을 0으로
채우는 것.** 서브넷 예약 IP를 몰라서 256으로 답하던 것과 같은 모양이고, 그때보다
나쁩니다(예산은 사람이 그 숫자로 결정하니까).

## 설계 판단 — 합계가 아니라 **가격표**

번들 비용 질의는 하나의 숫자가 아니라 **줄 목록**을 돌려줍니다.

```
core::vm 을 고르면 함께 만들어지는 것:

  값을 매길 수 있음
    core::vm      aws+ap-northeast-2+t3.medium   $0.0416/h
                  ⚠ 버스트 인스턴스 — 크레딧이 소진되면 baseline으로 떨어짐

  값을 매길 수 없음 (이 데이터셋에 가격 축이 없음)
    core::vNet · core::subnet · core::securityGroup · core::sshKey
    core::image (값을 반드시 줘야 함)

※ 합계를 내지 않습니다 — 위 4종의 단가를 모르는 채로 더하면 실제보다 낮은
  숫자가 나옵니다.
```

`cost_recommend_specs`가 성능 경고를 다는 방식(`_perf_annotate`)과 같은 모양입니다 —
**침묵을 안전 신호로 오독하지 않도록 "왜 비어 있는지"를 블록 끝에서 한 번 밝힙니다.**

## 조사 중 나온 데이터 결함

`tumblebug` 번들 23건 중 **13건이 같은 멤버를 여러 번** 담습니다(위 항목 3).
축을 연결하려고 멤버를 훑다가 나왔습니다 — 연결이 없었으면 안 보였을 결함입니다.

## 근거 등급은 다리를 건너며 떨어진다

다리의 두 링크는 등급이 다릅니다. 이걸 뭉개면 안 됩니다.

| 링크 | 근거 | basis |
|---|---|---|
| `core::vm → core::spec` | `swagger-field` | 원본 명시 |
| `core::vm ↔ aws::AWS::EC2::Instance` | `cb-spider-driver` | **짐작(검수됨)** |

즉 **벤더 타입에서 출발한 비용 답은 짐작 한 단계를 거칩니다.** `core::vm`에서
출발하면 안 거칩니다. `needs_hedge`가 이미 이 구분을 알고 있으므로, 답에 그대로
실으면 됩니다 — 새 규칙이 필요 없습니다.

| 2 | k8s 템플릿이 `core::cluster`라고 적었는데 **그런 노드가 없다**. 앵커도 같아서 `bundle_for_resource('core::k8sCluster')`가 아무것도 못 찾았다 | `core::k8sCluster` + 노드 그룹까지 담음 |

`Bundle.__post_init__`이 중복 타입에 **예외를 던집니다.** 조용히 합치지 않는 이유는
note를 어떻게 할지가 파서가 원본을 보고 내릴 판단이기 때문입니다. `count`는 1이면
산출물에 적지 않습니다 — 거의 다 1이라 다 적으면 1이 아닌 곳이 안 보입니다.

avm 207 · kcc 296 · aws-patterns 52는 중복 0건이라 **이 파서만의 문제**였습니다.
재빌드 후 중복 0건, 매달린 타입 id 0건.

> **곁다리로 확인한 것**: AVM이 말하는 `Microsoft.Insights/diagnosticSettings`와 우리
> 그래프의 `microsoft.insights/diagnosticSettings`는 **대소문자만 다릅니다**(ARM은
> 대소문자를 안 가립니다). `bundlekb`의 조회는 이미 소문자로 정규화하므로 영향이

엮는 일은 도구 계층에서만 할 수 있습니다. `cost_tools._perf_annotate`(costkb × perfkb)가
이미 그 자리이고, 여기서 **bundlekb × graphkb × costkb × perfkb** 넷을 잇습니다.

```
vm 을(를) 고르면 — 리소스 군과 그 값  [tumblebug 동적 VM 생성]

[값을 매길 수 있는 것]
  vm  aws ap-northeast-2 t3a.medium  2 vCPU / 4.0 GiB  $0.0468/h
      월 약 $34.16 (730시간 기준)
      ⚠ 버스트 인스턴스 — CPU 크레딧이 소진되면 baseline 성능으로 떨어집니다.

[값을 매길 수 없는 것 — 이 데이터셋에 가격 축이 없음]
  (반드시 함께 만들어짐) securityGroup · sshKey · subnet · vNet
  (값을 반드시 줘야 함) image

※ **합계를 내지 않습니다.** …
※ 같은 리소스를 중심으로 한 다른 계획 16개도 있습니다(…). 이름을 주면 그 계획으로 답합니다.
```

## 설계에서 되돌린 것 셋 — 전부 실측이 뒤집었다

**(1) 값이 붙는 개념을 손으로 적지 않는다.** 처음엔 `_PRICEABLE = "core::vm"`으로
박았는데, 그래프에서 끌어오게 바꾸니 `core::k8sNodeGroup`이 **자동으로 따라왔습니다**
(`core::k8sNodeGroup --references via specId--> core::spec`이 원본에 있습니다).
손으로 적었으면 쿠버네티스 노드 값이 조용히 빠졌을 것입니다.

**(2) 한 번에 한 계획만 본다.** `bundles_for('core::vm')`은 **17벌**을 돌려줍니다.
전부 늘어놓으니 같은 VM 값이 17번 찍히고 **서로 다른 계획이 한 계획처럼** 읽혔습니다.
`default_bundle_for`를 두어 "요청만 하면 도구가 하는 일"(동적 생성)을 기본으로 하고,
나머지는 이름만 알립니다.

**(3) "값이 안 붙는다"의 이유가 둘인데 뜻이 반대다.** 가격 축이 아예 없는 것과, 축은
있는데 이번 조건으로 못 고른 것을 한 칸에 넣었더니 앞의 것이 *"조건을 바꾸면 나온다"*로,
뒤의 것이 *"원래 공짜"*로 읽혔습니다. 칸을 갈랐습니다.

## 프로브 넷을 더했다 — 그리고 둘이 실제로 실패했다

앞의 38건은 **전부 단일 축 조회**였습니다(`want_tools` 2개 이상 0건, `record_plan`·
`cost_estimate_monthly`를 기대하는 프로브 0건). 목표 2의 동사가 측정 밖이었습니다.

| | 무엇을 지키나 | 첫 결과 |
|---|---|---|
| GL1 | 리전 해석 → 군과 값 (2단계) | ✓ |
| GL2 | "숫자만 달라"고 해도 한계를 밝히는가 | **✗ → 지시문 보강 후 통과(불안정)** |
| GL3 | 값 붙는 것과 안 붙는 것을 가르는가 | **✗ → 도구 설명 보강 후 통과** |
| GL4 | 계획 → 추천 → 비용 다단계 | ✓ |

**GL3의 첫 실패가 이 라운드에서 가장 값어치 있습니다.** 리전을 안 밝힌 물음에
모델이 **도구를 아예 안 부르고** EBS·ENI·Elastic IP를 기억으로 지어냈고, 주장 대조가
구체값 4개를 잡았습니다. 원인은 도구 설명이 리전을 필수처럼 읽히게 쓴 것이었습니다 —
*"비워도 된다"*를 적자 호출로 바뀌었습니다. **모델이 아니라 우리 도구가 문제였던
그 실패 모양이 또 나왔습니다.**

**GL3의 두 번째 실패는 기대가 틀렸습니다.** "짐작 고지가 답에 있나"를 기대했는데,
그 고지는 **벤더 타입으로 물었을 때만** 나옵니다. 모델이 `core::vm`으로 정규화하면
건널 다리가 없어 고지할 것도 없습니다. 도구가 어느 인자로 불릴지를 검사하는 것은
사실이 아니라 **경로를 고정**하는 것이라, 그 계약은 `test_guideline_join.py`가 단위로
고정합니다. (`H1`/`H2`·`R1`에서 이미 두 번 겪은 모양입니다.)

**GL2는 불안정합니다.** "딱 숫자로만"이라는 압박에 모델이 한계 고지를 버리는 회차가
있습니다. 지시문에 *"숫자만이라고 해도 이 한 줄은 빼지 마세요"*를 박아 2/2 중 1회차가
통과로 바뀌었지만 **결정적이지 않습니다.** 숨기지 않고 적어 둡니다.

## 전수 실행에서 나온 것 — **통과한 프로브가 틀린 답을 냈다**

42건 전수: **통과 41 · 실패 1 · 불안정 1**. 그런데 중요한 것은 실패가 아니라
**GL1이 통과하면서 낸 답**이었습니다.

```
도구:  [값을 매길 수 없는 것 — 이 데이터셋에 가격 축이 없음]
         (반드시 함께 만들어짐) securityGroup · sshKey · subnet · vNet

답변:  보안 그룹, VPC, 서브넷, SSH 키: 별도 요금이 부과되지 않음(무료)
```

**도구가 "모른다"고 한 것을 답변이 "0원"으로 뒤집었습니다.** 이 프로젝트가 막으려는
그 실패 그대로입니다 — 서브넷 예약 IP를 몰라서 256이라 답하던 것과 같은 모양이고,
사람이 그 숫자로 예산을 정하므로 그때보다 아픕니다.

**숫자 대조로는 절대 안 걸립니다** — 지어낸 숫자가 없기 때문입니다. `가능:`/`불가:`
뒤집기와 같은 부호 뒤집기이고, 같은 이유로 기계로 잡을 수 있습니다.

### 이름 대조로 짰다가 0건이 나왔다

처음엔 `_unpriced_members`로 도구가 쓴 이름(`securityGroup`·`vNet`)을 뽑아 답변에서
찾게 짰는데 **한 건도 안 걸렸습니다.** 답변은 **"보안 그룹"·"VPC"**라고 씁니다 —
모델이 옮겨 적으므로 토큰 대조는 살아남지 못합니다.

`misattributed`와 같은 논리로 바꿨습니다 — **우리 도구는 어떤 리소스도 공짜라고
말하지 않습니다.** 그러니 값의 출처가 우리 도구뿐인 답변에 공짜 단언이 있으면 그건
구성상 근거가 없습니다. 우리 고지("무료라는 뜻이 아닙니다")를 옮긴 부정절은 뺍니다 —
**답변이 우리가 시킨 말을 옮긴 것을 위반으로 세면 옳은 행동을 벌하게 됩니다.**

### 고친 뒤 — 5분의 4가 줄었고, 하나가 남았다

도구 출력의 그 칸 바로 아래에 *"**무료라는 뜻이 아닙니다.** … 실제로는 과금될 수
있습니다"*를 붙였습니다. 재실행:

```
보안 그룹  가격 데이터베이스에 비용 정보가 없으므로 별도 과금 여부는 확인이 필요합니다  ✓
서브넷     비용 데이터베이스에 가격이 포함되지 않음                                  ✓
VPC        가격이 없으므로 실제 청구 시 확인 필요합니다                              ✓
이미지     이미지 자체 비용은 없지만 … 추가 비용이 발생할 수 있습니다                 ✓
SSH 키     비용 없음(무료 제공)                                                  ✗ 남음
```

**4건이 고쳐졌고 1건이 남았습니다.** 지시문이나 문구를 더 만져 마저 없앨 수도 있지만,
그건 이 한 회차를 초록으로 만드는 일이지 문제를 푸는 일이 아닙니다. **남은 것을
적어 두고 검사가 매번 잡게 두는 쪽**을 택했습니다 — `flipped`를 넣을 때 *"31건 중
1건에만 적용되고 문제가 풀린 것은 아니다"*라고 적은 것과 같은 태도입니다.

### 곁다리 — 3-1은 기대가 틀렸다

유일한 실패 3-1("계정에 떠 있는 VM 목록")은 답변이 *"조회하는 기능은 **제공되지
않습니다**"*였는데, 후보 목록에 그 표현이 없어서 **정확한 거절을 실패로 찍었습니다.**
거절하는 말은 여러 가지라 후보를 좁게 잡으면 옳은 행동을 벌합니다 — 이 세션에서만
기대가 틀린 것이 세 번째입니다.

## 곁다리 — 근거 없는 `730`

주장 대조가 GL1·GL3에서 `730`을 잡았습니다. 월 비용의 시간 기준인데, 도구가 값만
주고 **기준을 안 실어서** 모델이 기억에서 꺼내 쓰고 있었습니다. 맞는 값이지만 그 턴의
도구 출력에 없는 값이라 원칙상 같은 종류의 위험입니다 — 출력에 `(730시간 기준)`을
함께 싣게 고쳤습니다.
