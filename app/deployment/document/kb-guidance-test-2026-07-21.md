# 리소스 특성 가이드라인 — 직접 테스트 결과 (2026-07-21)

**질문**: 지식베이스가 사용자에게 *리소스 특성에 맞는 가이드라인*을 제대로 주는가?

**방법**: 실제 사용자 질문 모양 8가지를 에이전트 API에 직접 태워, **사용자가 보게 될
문장 그대로**를 뽑아 읽었습니다. 모델을 거치지 않았습니다 — 모델을 끼우면 KB가 준
문장이 나쁜 건지 모델이 못 읽은 건지 구별할 수 없기 때문입니다.

재현: `tools/kb_audit/` 아래 스크립트. 기준선 `uv run pytest` **544 통과**.

## 1. P1 — KB가 답을 쥐고도 "모른다"고 말한다

**가장 심각합니다.** 다른 결함과 달리 이건 *사용자를 잘못된 방향으로 보냅니다.*

```
질문: gp2 볼륨을 30,000 GiB로 만들 수 있어?
답변: 알려진 제약이 없어 판정할 수 없습니다. 공식 문서를 확인하세요.
```

그런데 KB 안에는 이 문장이 들어 있습니다:

```
gp2: 1 - 16,384 GiB / gp3: 1 - 65,536 / io1: 4 - 16,384 /
io2: 4 - 65,536 / st1·sc1: 125 - 16,384 / standard: 1 - 1024
```

**gp2는 16,384가 상한입니다. 30,000은 명백히 불가능하고, KB는 그걸 알고 있습니다.**
그런데 "모른다"고 답하고 사용자를 공식 문서로 돌려보냅니다.

### 왜 이렇게 되나

`capacitykb/query.py:158` — 신뢰도 낮은(`basis=inferred`) 제약은 **위반했을 때만**
advisories에 담깁니다. 범위 안이면 아무것도 기록되지 않아 `checked`가 0이 되고,
판정이 `unknown`으로 떨어집니다. 그리고 `agent_api.py:154`의 `unknown` 분기는
**advisories를 출력하지 않고 조기 반환합니다.**

즉 약한 근거는 **의심을 키우는 데만 쓰이고, 알려주는 데는 안 쓰입니다.** 비대칭입니다.

이건 fail-open 원칙과 무관합니다. fail-open은 "짐작으로 막지 마라"이지
"짐작을 숨겨라"가 아닙니다. 오히려 **가진 정보를 숨기는 쪽이 원칙 위반에 가깝습니다.**

### 고칠 방향

`unknown` 분기에서도 advisories를 출력하고, 문구를 사실에 맞게 바꿉니다:

```
확정된 제약은 없습니다. 다만 참고 정보상 이 값은 범위 밖입니다:
  - gp2: 1 - 16,384 GiB (근거 cfn-description, 짐작)
공식 문서로 확인하세요.
```

나아가 **범위 안일 때도** 근거를 밝히는 게 맞습니다 — "확정 제약은 없지만 참고상
1–65,536 안에 듭니다"가 "모릅니다"보다 훨씬 쓸모 있습니다.

## 2. P1 — 봉투 붕괴: 6개의 서로 다른 범위를 한 칸에 뭉갰다

위 사례의 뿌리입니다. `Volume.Size`의 실제 제약은 **볼륨 종류마다 다릅니다.**
그런데 데이터셋에는 이렇게 들어갑니다:

| | 저장된 값 | 실제 |
|---|---|---|
| `Size` min | **1** | gp2 1 / io1 4 / st1·sc1 **125** |
| `Size` max | **65,536** | gp2 **16,384** / gp3 65,536 / standard **1,024** |
| `Iops` min | **100** | gp3 **3,000** / io1 100 |
| `Iops` max | **256,000** | gp3 **80,000** / io1 **64,000** / io2 256,000 |

최솟값 중 최소, 최댓값 중 최대를 취해 **어떤 실제 설정에도 해당하지 않는 범위**가
됐습니다. `standard` 볼륨에 5,000 GiB는 불가능한데(상한 1,024) 이 봉투는 통과시킵니다.

**해당 건수는 4건입니다** (`conditional=True`가 붙은 전체 7건 중). 규모는 작지만
**종류가 문제입니다** — "이 속성의 한계는 저 속성 값에 따라 다르다"를 담을 칸이
지금 스키마에 없어서, 담으려면 note 자유 서술로 흘려보내는 수밖에 없습니다.

> 다행히 지금은 **틀린 초록불을 켜지 않습니다** (약한 근거라 판정에서 빠짐).
> 위험한 건 봉투 값이 언제라도 `basis=stated`로 승격되면 그 순간 **확신에 찬 오답**이
> 된다는 점입니다. 승격 전에 구조를 고쳐야 합니다.

## 3. P2 — 위험한 것과 안 위험한 것을 같은 목소리로 나열한다

"RDS에서 나중에 못 바꾸는 게 뭐야?" → **31개를 알파벳순으로** 쏟아냅니다.

```
- AutoMinorVersionUpgrade: 조건부 변경 불가 ...
- AvailabilityZone: 조건부 변경 불가 ...
- BackupRetentionPeriod: 조건부 변경 불가 ...
- BackupTarget: 생성 후 변경 불가 ...
...
- MasterUsername: 생성 후 변경 불가 ...
```

`MasterUsername`을 잘못 잡으면 **DB를 재생성**해야 하고 데이터가 날아갑니다.
`AutoMinorVersionUpgrade`는 그냥 재부팅 수준입니다. **둘이 나란히 같은 말투로 있습니다.**
그리고 `MasterUsername`은 알파벳순이라 목록 중간에 파묻힙니다.

이게 사용자가 물은 "가이드라인"의 핵심입니다. KB는 **"못 바꾼다"는 알지만
"그래서 얼마나 아픈가"는 모릅니다.** 알파벳순 나열은 가이드라인이 아니라 목록입니다.

**고칠 방향** — 최소한 `create_only`를 `conditional_create_only`보다 위로 올리고,
"재생성" 여부로 묶어 보여주는 것만으로도 크게 나아집니다. 진짜 위험도(데이터 손실 여부)는
별도 정보라 손 검수 표가 필요합니다.

## 4. P2 — 리전 중복이 추천 자리를 다 먹는다

```
질문: vCPU 2 / 메모리 4GiB, 6개 추천해줘
답: TENCENT S5.MEDIUM4 (ap-chengdu)
    TENCENT BF1.MEDIUM4 (ap-chengdu)
    TENCENT S5.MEDIUM4 (ap-chongqing)   ← 같은 스펙
    TENCENT BF1.MEDIUM4 (ap-chongqing)  ← 같은 스펙
```

**6칸을 요청했는데 실제로 본 스펙은 3종**입니다. GCP도 마찬가지로 `e2-highmem-8` 하나가
3개 리전으로 3칸을 다 차지했습니다. 리전을 지정하지 않은 사용자는 **선택지를 비교하고
싶은 것**인데, 같은 것을 여러 번 보게 됩니다.

perfkb는 이미 `_fold_regions()`로 리전을 접는데 costkb 추천에는 그게 없습니다.

## 5. P3 — 경고가 엉뚱한 줄에 붙는다

```
  EBS 지속 대역폭: 347.0 Mbps
  EBS 최대 대역폭: 2085.0 Mbps
    ⚠ 네트워크 대역폭이 버스트('Up to')라 지속 값이 아닙니다.
```

이 `⚠`는 **네트워크** 이야기인데 들여쓰기 때문에 **EBS 최대 대역폭**에 달린 것처럼

네트워크 버스트는 다른 사안이라 오해가 실제 판단을 바꿉니다.

## 6. P3 — 내부 식별자가 API 밖으로 샌다

```
aws::AWS::EC2::Subnet 의 변경 시 재생성되는 속성 11개:
  - AvailabilityZone: ... (근거 cfn-schema, 원본에 명시됨)
```

`aws::` 접두사와 `cfn-schema`·`cdk-oob`·`heuristic` 같은 근거 라벨이 그대로 나옵니다.
질의집 체크리스트 12번이 "프롬프트로만 막혀 있어 특히 잘 샌다"고 적어둔 항목인데,
**애초에 API가 내보내고 있습니다.** 프롬프트에 지우라고 시키는 것보다 API가 안 만드는
편이 확실합니다(근거는 남기되 사람 말로).

## 7. 그래서 "칸이냐 자연어냐"에 대한 답 — 숫자로

지난 세션의 미해결 질문에 이번 테스트가 근거를 줬습니다. **원본을 직접 열어 셌습니다.**

CFN 스키마 1,635개, 설명문이 있는 속성 **6,339개**. 그중 우리가 뭔가를 뽑아낸 건
**58개(0.9%)**입니다. 나머지에서 *규칙을 말하고 있는* 문장을 유형별로 세면:

| 유형 | 건수 | 실제 예시 |
|---|---:|---|
| 다른 속성에 의존 | 130 | "stage description을 쓰려면 stage name도 함께 줘야 한다" |
| 열거값이 산문에만 | 37 | "must be one of ACCOUNT, ORGANIZATION, ..." |
| 변경 불가인데 스키마엔 없음 | 24 | "Immutable after creation" |
| 변종마다 다름 | 6 | "RabbitMQ면 사용자 1명, ActiveMQ면 Password 외 변경 무시" |
| **되돌릴 수 없음** | 4 | "once it is enabled **it cannot be disabled again**" |
| 쓰기 전용 | 1 | "This property is write-only" |
| **중복 제외 합계** | **198** | 설명문 있는 속성의 **3.1%** |

### 여기서 정직하게 짚을 것

처음엔 "산문의 99%를 버리고 있다"고 볼 뻔했습니다. **틀렸습니다.** 6,339개 설명문의
대부분은 규칙이 아니라 그냥 설명이고, 규칙을 말하는 건 **198개(3.1%)**입니다.

더 확인해보니, "변경 불가"를 말하는 산문 16건 중 **13건은 이미 스키마에도 있어서
우리가 압니다.** 산문에만 있어 놓친 건 **3건**뿐입니다. 즉 **불변성에 관한 한
스키마가 제 일을 하고 있고, 산문을 읽어도 별로 안 늘어납니다.**

### 결론

**"칸이 부족하다"는 진단은 절반만 맞습니다.**

- **양으로는 작습니다.** 198건, 3.1%. 산문 파서를 크게 만들 이유가 안 됩니다.
- **그런데 종류가 지금 칸으로 표현이 안 됩니다.** 특히 두 가지:
  - **"다른 속성에 의존"(130건)** — 가장 많고, `Volume.Size`의 봉투 붕괴와 **같은 뿌리**입니다.
    이건 자유 서술이 아니라 **관계를 담는 칸**이 필요합니다
    (`when: {VolumeType: gp2} → max: 16384` 꼴).
  - **"되돌릴 수 없음"(4건)** — 건수는 적지만 **틀렸을 때 가장 아픈 종류**입니다.
    "바꾸면 재생성"과 "한 번 켜면 영영 못 끈다"는 전혀 다른 경고인데 지금은 후자를
    담을 칸이 없습니다.

**제안하는 방향**: 자유 서술로 도망가지 말고, **조건부 제약을 담을 칸을 하나 만드는 것**을
먼저 시도할 것을 권합니다. 130 + 6 + 4 = 140건이 그 칸 하나로 해결되고, 그러면
불변식으로 검사할 수 있고 재현도 됩니다. 자유 서술은 **그러고도 안 담기는 것**에만
쓰는 게 맞습니다 — 지금 note 채널은 53,657건 중 **10건**만 쓰고 있어서, 사실상
설계된 적이 없는 통로입니다.

### 고친 내용 (①④⑤⑥)

**①** `CheckResult.references` 신설 — 약한 근거가 **벗어나지 않았을 때도** 남긴다.
`check()`의 `unknown` 분기가 그걸 출력한다. 이제 "gp2 30,000 GiB"에 볼륨 종류별
상한표를 함께 내놓는다. 진짜로 근거가 없을 때는 여전히 "알려진 제약이 없습니다"다.

**④** `costkb/dataset.py:_fold_regions()` — 정렬 뒤 `(provider, specName)`으로 접는다.
정렬 후에 접으므로 남는 레코드가 곧 그 스펙의 최선(비용 정렬이면 최저가)이다.
값은 고쳐 쓰지 않고 접힌 리전만 `_foldedRegions`에 남긴다(미러 원칙).
표시는 `us-east-1 외 6개 리전` — 숨기면 "이 리전에만 있다"는 거짓 인상을 준다.

> 효과가 컸다. `limit=6`에 **실제 스펙 3종 → 6종**. 접기 덕에 밀려 있던
> `ecs.t5-lc1m2.large`(결함 C4의 재현 사례)가 비로소 목록에 올라왔다.

**⑤** 경고를 블록 끝이 아니라 **해당 줄 바로 밑**에 붙인다.

**⑥** `kbcommon/display.py` 신설 — `display()`가 `aws::` 접두사를 떼고,
`evidence_name()`이 `cfn-schema` → "CloudFormation 스키마"로 바꾼다. 근거를 없애는 게
아니라 사람 말로 적는 것이다. capacitykb·graphkb의 agent_api에 적용했다.

### 검증

회귀 테스트다 — 범위 안 약한 근거 보존, unknown 분기 출력, 식별자 은닉, 리전 접기 4종,
경고 위치. 기존 테스트 3건은 옛 라벨(`cfn-schema`)을 문자로 고정하고 있어 새 계약으로
바꿨다(근거를 밝히는지는 계속 검사하되, 사람 말로 밝히는지를 본다).

> 실행 시간이 25초 → 111초로 늘었는데 **이번 변경과 무관하다.**

> 나머지는 552건 × conftest의 캐시 비우기 오버헤드다. 별도 과제로 남긴다.
